# 应用目录与原目录更新

每个项目使用一个固定目录，直接保存代码和运行所需文件。更新在这个目录完成，不建立多版本目录、切换链接、旧版本保留或自动回退流程。

## 默认目录

新部署使用实际部署账号家目录下的 `apps/<project>/`。root 示例：

    /root/
      apps/
        translator/
          项目代码与启动配置
          .venv/          # Python 项目按需创建
          data/           # 业务数据按需创建，更新时保留
          uploads/        # 上传文件按需创建，更新时保留
        another-project/
      server-deployments.md
      server-credentials.md  # 使用凭据库时生成

普通账号使用其实际家目录，例如 `/home/deploy/apps/translator/`。先核实部署账号、家目录和解析后的项目绝对路径，避免误用本机路径、临时 sudo 后的 `~` 或带路径穿越的项目名。保留项目本身的文件结构，不为了统一外观额外包一层 src，也不强制创建项目不需要的目录。Nginx、systemd 等配置继续使用各自标准位置。

持久化数据可以放在项目内的独立目录，但必须排除出代码同步、覆盖和清理范围；已有数据目录、挂载点和数据库位置优先保留。凭据库、identity 和受信任的凭据启动器按 [凭据规范](credentials.md) 保存在应用代码树外。

部署账号和应用运行账号分别确定。需要隔离时继续使用专用非 root 应用账号，并验证它能访问项目所需文件；`/root` 通常受限，按实际方案授予必要的目录访问权限或仅挂载该项目到容器。不能开放整个家目录或让应用长期以 root 运行来绕过权限问题；无法满足要求时按适配规则阻断。

已有应用先核实真实目录、符号链接目标及启动配置，默认在实际目录更新，不因为新规范擅自搬家。现存多版本目录不能直接当垃圾删除；只有迁移属于本次任务且依赖核实清楚时才调整。

## 更新前确认

查阅目标版本的部署说明及启动配置，按 [项目部署文档的适配规则](../SKILL.md#项目部署文档的适配规则) 核对本次变化。根本冲突未解决或关键适配未验证时，不修改线上代码、不停旧服务；可以继续独立准备工作。

以部署账号读取 `~/server-deployments.md`，核实当前版本、固定应用目录、访问地址、端口、服务单元、运行账号及凭据引用。列出数据库、上传、业务文件、本机配置、挂载点等实际持久化路径，检查工作区是否有未提交修改。只输出必要且脱敏的信息。按默认策略核验 HTTPS，沿用满足要求的既有入口。

涉及数据迁移时，先核实兼容性和项目要求的数据保护措施，不能把原目录更新当成删除数据库或重新初始化业务数据的授权。若有破坏性操作超出本次授权，先完成其他准备并说明阻塞。

## 在固定目录更新

1. 明确要部署的版本，先完成可独立进行的下载、依赖核验和构建检查。临时工作目录只用于准备，完成后清理，不成为运行路径或历史版本。
2. 按项目支持的方式更新代码和锁定依赖。需要覆盖运行文件或重建运行依赖时，先停止本应用，再执行更新；可能短暂停机，不承诺无中断。不能用强制重置或清理命令丢弃未核实的本地修改。
3. 同步代码时显式保护已确认的持久化路径、本机配置及挂载点；涉及删除先 dry-run 并检查清单，不使用未经核实的全目录 `rsync --delete` 或 `git clean`。排除项按真实项目确定，不能只保护示例中的 data 和 uploads。
4. Python 虚拟环境在固定项目路径创建或重建，不搬入其他路径下建成的环境。Compose 沿用核实后的项目名、卷名和挂载路径；更新服务不能顺带删除数据卷。
5. 按项目需要完成已确认的迁移、构建和启动，只操作本项目相关服务。保持凭据引用和稳定启动器路径，代码更新不顺带轮换凭据。

## 配置与验证

入口、端口和启动方式不变时无需重写配置。必须修改时先校验，避免影响其他应用：Nginx 配置临时保存原文件与权限，`nginx -t` 通过后才 reload；失败还原本次配置改动并重新核验。新增错误文件须撤出 include 范围。验证完成后清理本次临时副本，不形成版本保留机制。其他入口使用其对应的校验方式。

unit 修改后执行 daemon-reload，再启动或重启指定服务。核对实际进程、后端健康接口、真实域名入口、外部访问，以及登录或一次最小业务操作；HTTPS 验证使用正确域名、SNI 和证书，不关闭证书校验。详见 [入口验证](nginx-port-mode.md#验证实际入口)。

按正常启动时间设置有限的重试次数。失败时保留脱敏诊断并定位问题；能够在授权范围内修复则修复并重新验证，仍失败就停止继续发布，明确服务是否停止、目录内实际版本、影响和阻塞。不能假定旧版还在正常运行，也不自动切回旧代码。

## 清理与登记

仅清理核实无用的临时传输文件和构建缓存；递归删除前核对解析后的绝对路径、符号链接和挂载点，不能误删项目目录、依赖、业务数据或凭据。数据和凭据原有的备份措施继续保留，不因此增加应用历史版本。

最后更新同一项目/服务器行，用中文记录固定目录、实际版本、运行状态、验证结果、持久化位置、凭据引用及安全状态。失败也要记录当前事实，区分“上次验证通过”与“本次仍可用”，不把计划或未经核实的旧记录当成部署成功。
