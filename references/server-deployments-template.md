# 服务器部署登记表

本清单保存在本机部署账号的 `~/server-deployments.md`，每个项目一行。如需标明主机，可在此处填写一次。新项目默认位于该账号的 `~/apps/<project>/`，已有项目填写实际目录。分配端口时还要核对实际监听和入口配置。

## 端口约定

| 用途 | 建议端口或范围 | 说明 |
|---|---|---|
| HTTP 入口 | 80 | 默认用于 HTTPS 跳转或证书验证；业务 HTTP 例外须记录原因与访问范围。 |
| HTTPS 入口 | 443 | 多个域名可共用，由实际网关按域名分流。 |
| 额外独立公共入口 | 12001–12999 | 没有域名路由时使用，仍需确认访问控制与传输保护。 |
| 后端服务 | 18001–18999 | 默认仅绑定 127.0.0.1，不直接向公网开放。 |

## 部署记录

| 项目 | 已部署版本 | 访问地址 | 用户端口 | Nginx 监听端口 | 后端绑定地址 | 后端端口 | 进程管理器 | 服务单元/进程 | 应用目录 | 健康检查 | Nginx 配置 | 安全措施 | 更新日期 | 备注 | 凭据引用 |
|---|---|---|---:|---:|---|---:|---|---|---|---|---|---|---|---|---|

已部署版本填写已核实的 Git 提交、镜像摘要或发布版本，无法确认时留空。安全措施记录实际访问控制。备注可写运行账号、持久化目录、更新命令和最近验证结果。凭据引用只填写 project/environment/name。

使用其他 Web 网关时用 `upsert --no-nginx`，在备注中记录实际网关与配置位置。无入口的独立服务或定时任务用 `upsert --no-ingress`，地址与端口留空，填写实际服务单元和结果核查方式。
